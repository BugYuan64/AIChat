# AIChat

AIChat 计划提供类似微信的独立聊天 App，让人类与拥有独立平台账号的 AI 私聊、建群，后续加入受控的多 Agent 协作。
先交付 Android App，再扩展 H5 和微信小程序；iOS 为可选后续平台。

**当前只有中文设计文档，无项目实现、可运行入口、已接通 AI 或可安装 App。**
本轮完成初期产品、架构、协议和实施步骤设计；文中技术与流程均是实现依据，不代表功能已上线。

## 需求与范围

- 人类与 AI 都有独立账号；同一厂商可对应多个独立 AI 实例。
- 支持人类私聊、人与 AI 私聊、多人群聊、联系人及群成员管理。
- 统一 AIChat Connector 协议，由 runner 与各运行时或模型 adapter 桥接。
- 手机批准扫码配对，绑定 owner、AI 账号与 runner；无需每个 Agent 注册微信号或修改微信客户端。
- 默认仅 AI 私聊或人类明确 @AI 触发任务，群消息不会自动广播给全部 AI 执行。
- Hermes、Codex、Claude、Gemini、ZCode 都是目标接入对象，本项目当前均未完成业务接入。
- 后续有限协作受预算、轮次、并发、工具权限和人类审批约束。

首期以自用为入口，数据模型仍隔离不同 owner。不包含支付、朋友圈、语音视频、附件执行、纯 AI 群聊。
后台推送、iOS 和第三方编排的上线均需另行实现验收。

## 设计默认技术栈

| 部分 | 已采纳的可调整设计默认 | 作用 |
| --- | --- | --- |
| 客户端 | 传统 uni-app、Vue 3、TypeScript | Android 优先，复用业务到后续平台 |
| 客户端状态 | Pinia 可选 | 缓存界面状态，不作为消息或权限权威 |
| 服务端 | Node.js LTS、TypeScript、NestJS 模块化单体 | 集中事务与鉴权，降低首期部署成本 |
| 通信 | HTTPS REST、标准 WSS JSON | REST 命令与补拉，WSS 事件与 runner 控制 |
| 数据 | PostgreSQL | 消息、成员、事务 outbox、持久任务队列 |
| runner | 用户 Windows/Linux 上的独立进程 | 主动出站连接，封装运行时，不暴露本地 CLI 端口 |

版本和移动工具链在实现阶段确定；首期不依赖 Redis、Kafka、Kubernetes 或对象存储。
这些选择不是用户最终技术审批；依据和上游事实见[设计决策与验收](docs/设计决策与验收.md)。
