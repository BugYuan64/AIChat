# 模板验证记录

日期：2026-10-26。对象：本目录 `prototype.html`，不是生产客户端。

## 方法与结果

通过只监听 `127.0.0.1` 的临时静态服务加载模板，使用现有本地 Playwright 浏览器执行检查。没有安装依赖，也没有访问正式站点或真实账号。Playwright CLI 本地缓存不可用，因此使用已连接的本地 Playwright 工具完成验证。

### 交互检查

35 项断言通过，覆盖：

- 人类私聊隐藏 AI 目标按钮和空身份标签；群聊选择、移除 AI 后提示更新。
- 演示发送只将用户输入作为纯文本插入；形似 HTML 的输入不生成元素。
- 九种 RunState 全部有对应文案；请求停止保留“等待确认”；客户端断线提示可见。
- 会话本地筛选及无匹配结果提示。
- 运行详情打开/关闭、Tab 焦点进入、Esc 关闭、焦点回到触发按钮；嵌套抽屉同样回归原始按钮。
- 联系人、我的 AI、我的和登录演示可达；联系查找不冒充真实请求，AI 业务可用性显示未验证。
- 配对未核对不能批准；核对后仅展示等待设备端确认，不执行真实绑定。
- 深浅模式、窗口缩窄/放大自动切换布局、手机 AI 次级页返回、手机发送按钮高度。
- 复制 AI 回复只包含正文，不包括运行状态或操作按钮文案。

### 布局检查

最终模板在 1440 / 1024 / 900 / 768 / 430 / 390 / 360px 共七个视口宽度下，分别检查会话列表、聊天、联系人、我的、我的 AI：**35 个页面/宽度组合无水平溢出**。检查包括文档、应用容器和可见的主要内容区域，不等于已验证所有极端文本、字体缩放或系统键盘。

最终加载后的浏览器控制台无错误、无警告；网络记录仅有本机模板文档请求，没有外部资源、API 或真实聊天请求。

## 设计复核

另由独立只读复核检查交接说明、模板和现有契约。已修正隐藏样式、嵌套抽屉焦点、复制范围、自动断点、手机返回和输入操作触摸区域。复核发现“获授权 AI 列表”的数据来源并非当前 `scope=owned` 接口，已将本轮范围收敛为我管理的 AI，其他 AI 继续通过联系人访问。

保留的后续产品决策：`recovery_required` 是否允许用户核查并确认后发起新运行。模板采用核查提示，不提供盲目重试入口；生产实施须统一聊天页和运行详情页的规则。
