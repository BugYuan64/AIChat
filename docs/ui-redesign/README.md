# AIChat 网页与 Android UI 改版交接稿

日期：2026-10-26。状态：**设计建议，供评审和转交；未改动业务客户端，未上线。**

## 1. 交付物与使用方法

- `prototype.html`：无需安装依赖的交互参考模板，直接用浏览器打开。可切换桌面/手机、浅色/深色，浏览会话、联系人、我的 AI、我的、登录；可体验消息发送演示、AI 选择、任务状态和详情抽屉。所有数据均为虚构，不连接真实服务。
- `handoff-prompt.md`：可直接交给设计师或代码生成工具的任务描述；与本文件一起转交。
- 本文件：现状判断、视觉参数、10 个现有页面的设计要求、状态文案、边界及验收清单。模板仅覆盖核心场景；未画出的页面以这里的文字说明为准。

模板是视觉与交互参考，不是可直接替换 uni-app 页面的生产源码，也不代表 Android 真机效果。原项目仍使用 `apps/mobile` 下的 uni-app + Vue 3 + TypeScript。

## 2. 从当前项目得到的判断

本轮直接读取了 `README.md`、`apps/mobile/src/pages.json`、`styles/base.scss`、各页面模板、`api/types.ts`、`docs/产品与交互.md` 和 `contracts/PROTOCOL.md`。现状判断来自代码，未登录正式站点，也未操作真实聊天数据。

| 现状 | 对体验的影响 | 对应改法 |
| --- | --- | --- |
| 三个底部 Tab 都只有文字；列表、标题和按钮大量依赖通用类 | 导航辨识度弱，各页面主次不明确 | 给导航统一图标、选中态和文字；每页只保留一个主要操作 |
| `.list-item` 没有通用的头像与正文间距；各页局部补样式 | 列表排列和密度容易不一致 | 统一 ConversationRow / AccountRow，明确 gap、头像、单行截断 |
| H5 与 App 共用移动端页面，未见桌面会话壳层 | 大屏仍像拉宽的手机页 | 桌面组合导航、列表和正文；手机按页进入 |
| 我的消息使用大面积亮蓝底，AI 回复与普通白气泡区别有限 | 长文本视觉重量大，AI 身份不够突出 | 浅色发送气泡，独立 AI 标签，AI 长回复使用可读内容块 |
| `agents/detail.vue` 同页堆叠档案、模型密钥、授权和连接器 | 日常聊天与偶发设置混在一起 | 简洁资料头＋接入方式＋折叠分组；密钥只在配置流程录入 |
| 配对页直接出现 pid / short_code；任务页主要是 ID 和时间字段 | 用户先看到内部术语，难以判断该做什么 | 优先展示设备、确认码、任务摘要与下一步，技术字段折叠 |
| `me.vue` 使用会话数量文案“台在线” | 活跃登录会话不等于设备当前在线 | 改为“登录会话”或“已登录设备”，不暗示实时在线 |

旧设计文档存在“所有页面待实现”等历史表述；实施状态以当前源码和 `contracts/PROTOCOL.md` 为准。当前 README 仍明确标注：群邀请接收 UI、Android 真机验收、真实模型厂商验收尚未完成。本轮不把它们视为已完成能力。

## 3. 风格方向与取舍

这是本稿的设计建议，并非已经过用户确认的品牌方案。

| 方向 | 观感与收益 | 代价 |
| --- | --- | --- |
| **默认：安静、清晰的协作聊天** | 中性浅底、墨色文字、少量青绿；适合长时间阅读，也适合 human-human 聊天 | 科技感较克制，靠细节而不是装饰形成品质 |
| 日常社交聊天 | 列表更紧凑、气泡更明显，熟悉且上手快 | AI 的长回复与任务状态更容易拥挤 |
| 专业 AI 工作台 | 更多面板、运行时间线和配置入口 | 容易弱化普通聊天，手机信息密度过高 |

采用默认方向：**聊天优先，AI 是有独立身份的参与者；配置和运行细节按需展开。** 不使用大面积紫蓝渐变、玻璃模糊、发光边框、装饰性数据卡片、夸张标题和大圆角卡片堆叠。保留品牌名 AIChat，不另造产品名。

## 4. 视觉规范

### 4.1 颜色

以下均为可调整的建议值。颜色必须通过语义变量引用，避免页面内散落硬编码。

| 语义变量 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--canvas` | `#F5F6F4` | `#111714` | 页面底色 |
| `--surface` | `#FFFFFF` | `#19211D` | 内容区、弹窗 |
| `--surface-soft` | `#F0F3F0` | `#222D26` | 搜索、次级区域 |
| `--text` | `#202923` | `#E8EEE9` | 正文 |
| `--text-secondary` | `#606D63` | `#ADBBB1` | 摘要、说明 |
| `--line` | `#E1E7E1` | `#354339` | 弱分隔；不可作为唯一控件识别线 |
| `--control-line` | `#7B877D` | `#83988A` | 需要独立识别的输入框边界 |
| `--accent` | `#216A50` | `#8AD8B1` | 主操作、焦点、选中 |
| `--on-accent` | `#FFFFFF` | `#10251A` | 主按钮文字 |
| `--accent-soft` | `#E8F2EB` | `#273F31` | 选中背景、自己消息 |
| `--ai` | `#63549A` | `#C3B6ED` | AI 身份的小标签 |
| `--ai-soft` | `#F0EDF7` | `#312B43` | AI 头像背景 |
| `--danger` | `#B13B38` | `#FFB4AC` | 失败、不可逆操作 |
| `--warning` | `#805515` | `#ECC887` | 等待、需处理 |

主要内容遵循常规文字至少 4.5:1 的对比度验收目标；大字、控件边界和焦点按对应可访问性标准另验。上述色值不是无障碍合格证明。状态总是同时使用文字，不仅靠颜色。

### 4.2 字体、尺寸与间距

- 中文沿用系统字体；网页字体栈建议 `-apple-system, BlinkMacSystemFont, "Segoe UI", "Microsoft YaHei", sans-serif`，不依赖外网字体。
- 正文 15–16px；聊天正文 16px / 1.65；页面标题 22–24px / 600；行标题 15–16px / 600；摘要 13–14px；时间等辅助信息 12px，重要错误不得缩到辅助字号。
- 使用 4px 间距基准：4 / 8 / 12 / 16 / 24 / 32。手机页边距 16px，桌面内容边距 28–40px。
- 按钮、输入框圆角 10–12px，列表选中背景 12px，弹层 16–20px。阴影只用于悬浮层，不给每行列表加阴影。
- 手机主要触摸区域至少 48×48 个逻辑像素；图标本身 20–24px。桌面常规按钮高 36–40px，输入框高 44px。
- 这些是视觉逻辑尺寸。现项目使用 rpx，实施时结合 750rpx 设计宽度和目标设备验证；不能把 16px 直接替换成 16rpx。桌面字号/栏宽不要随超宽视口同比放大。
- 图标统一用一种线性体系，同一笔画粗细；不能用 emoji、文字字符拼凑正式导航。模板中的小型线条图标仅作风格参考。

## 5. 双端布局与导航

### 5.1 桌面网页

默认工作界面是三部分：72px 导航栏＋296–336px 会话列表＋弹性聊天区。聊天正文最大宽度 760px，居中；头部与输入区固定，消息区独立滚动。导航依次为会话、联系人、我的 AI，底部放我的账号。

- ≥1200px：三部分完整显示；详情默认以 320–360px 浮层或覆盖抽屉打开，避免挤压聊天正文。只有空间足够且经评审需要时，才固定第四栏。
- 900–1199px：导航压缩为 64px，列表为 280px，详情覆盖显示。
- 768–899px：列表与聊天二选一；保留紧凑导航。
- <768px：按手机结构显示。不把三栏缩成三条窄栏。

网页的会话、联系人和 AI 页复用壳层。浏览器返回、刷新后会话定位属于实施验收项；不要假设目前已支持独立桌面路由。

### 5.2 Android

保留目前三个一级 Tab：**会话 / 联系人 / 我的**。不在这次纯视觉改版中新增第四个 Tab；“我的 AI”和“连接设备”在“我的”中提供清晰入口，联系人中可区分人类和 AI。

- 列表页：系统状态栏→56px 标题栏→搜索/列表→底部导航→系统手势区。
- 聊天页：返回＋头像/名称＋更多，底部不显示一级 Tab，输入区停靠键盘顶部。
- 次级页：返回＋标题，表单或设置分组；底部危险操作与主操作分开。
- 适配状态栏、安全区、软键盘、系统返回、横竖屏和系统字体放大。模板的手机模式只是浏览器模拟画布，不能替代这些验证。

## 6. 页面级设计要求

### 6.1 登录 / 邀请注册 — `pages/login/login.vue`

手机居中品牌标记与简短文案“和人类、AI，一起把事情聊清楚”，下方单列表单；桌面可用左右布局，左侧克制的产品示意，右侧宽 360–400px 表单。默认显示账号名、密码和登录；邀请注册增加邀请码、昵称。标签放输入框上方，不只用 placeholder。显示密码切换、提交中和行内错误，失败保留非秘密输入；密码不持久化到模板或本地演示数据。

服务器设置在底部折叠，展示“服务器地址”，说明 REST/WSS 等技术内容移至帮助。不要加入没有真实流程的短信登录、社交登录、找回密码、注册成功邮箱等入口。

### 6.2 会话列表 — `pages/sessions/sessions.vue`

标题“会话”，右侧新建；搜索框 placeholder“筛选当前会话”。这次可以做已加载会话的本地过滤，不能描述成全历史消息搜索。列表行建议高 76–84px，头像 44–48px，头像与文本间距 12px；第一行名称和时间，第二行消息摘要和未读。选中整行浅青绿，未读保留醒目圆点/数字。

AI 私聊名称旁有“AI”小标签；群聊用群头像和群名，不因为群里有 AI 就把整群标为 AI。预览最多一行，不展示技术 ID。暂无消息显示“还没有消息”；无会话空态显示“从一段对话开始”，提供“找联系人”“创建群聊”。新建入口使用菜单：发起私聊 / 创建群聊。若设计加入“置顶”，必须标注为新增功能，不在本稿默认范围。

### 6.3 聊天 — `pages/chat/chat.vue`

聊天头部：名称、明确的 AI/群身份；副标题只显示可信信息。群聊显示成员概况，私聊 AI 显示接入信息或“可用性未确认”。“已连接”应说明是客户端实时连接，不应混成所有 AI 都可用。更多入口通向群设置或对方资料。

普通他人消息靠左，自己消息靠右、浅青绿底；AI 消息保留头像、名称和 AI 标签，长文本采用宽一些的内容块。文字可选中、复制，引用块有左边线和来源；引用未加载时给出明确文案。群内每位发送者都能识别身份，不仅显示首字母。

AI 回复下方：流式中显示“正在生成”，停止操作是小型次按钮；成功后状态折叠，只保留复制和必要详情入口。不要凭空添加 token、费用、思考过程、工具轨迹等未提供数据。所有长文本/Markdown 应作为不可信内容处理；Markdown 是增强项，当前源码以文本渲染，不能在纯样式修改中悄悄启用原始 HTML。

输入区：输入框、@AI、发送。私聊人类不显示 AI 目标选择；私聊 AI 直接发送即可触发；群聊必须通过选择器选出 AI，最多 3 个，显示可移除 chip。只输入同名“@某某”文字不能冒充结构化 mentions。群聊未选择 AI 时提示“未选择 AI，这条消息只发送到群聊”。

网页 Enter 发送、Shift+Enter 换行；中文输入法 composition 期间 Enter 不发送。手机发送由独立按钮触发，不抢占输入法换行。输入为空、关闭或撤权时禁用发送并说明原因。用户向上查看历史时，新消息显示“有新消息”入口，不强行拉到底；贴近底部时才自动跟随。这属于交互改进，需要调整现有无条件滚动行为并单独验证。

### 6.4 联系人 — `pages/contacts/contacts.vue`

顶部分段“联系人 / 申请”，申请数只取真实数据。联系人行含头像、名称、handle 和 AI 身份；按人类/AI 进行视觉分组或本地筛选。添加联系人使用“输入完整账号名”，与本地筛选分开，避免暗示支持任意关键词发现用户。

收到申请用接受主按钮＋拒绝文本按钮；发出申请用“等待对方接受”，不要混进可正常聊天联系人。建群进入独立选择状态：顶部取消/下一步，列表多选，底部显示已选人数，再填写群名。发出邀请后显示“邀请已发送”，不能显示“成员已加入”。

### 6.5 我的 AI — `pages/agents/agents.vue`

本次“我的 AI”只展示我管理的 AI，对应当前 `listAgents('owned')`。获授权 AI 继续从联系人进入，不把 AI 联系人一律视为已获使用授权。若后续需要独立的“获授权 AI”列表，须先明确真实查询来源与权限，不凭空新增 scope。卡片以 48px AI 头像、名称、简介、接入类型和可核实状态构成；主要入口是“管理”，可以发起聊天的能力必须沿用当前授权判断。不要画与接口不符的公共 AI 商店。

空态“创建你的第一个 AI”，用一句话解释“AI 有独立账号，可接入模型或连接你的设备”。不在首页展示密钥表单。创建时收集当前接口需要的字段，具体绑定留到下一步。

### 6.6 AI 详情 / 接入管理 — `pages/agents/detail.vue`

资料头：头像、名称、handle、简介；下方分为“接入方式 / 使用授权 / 连接设备”。该管理页面向 owner；非 owner 不能因视觉重构获得管理入口。当前 `getAgent()` 还会读取授权清单，不能直接拿它给其他用户做只读资料页；非 owner 的资料展示应使用已有允许访问的有限账号资料，并另验权限。

模型 API 配置：连接方式分段、管理员预配置的服务商代码、模型名称、密码型密钥输入、可选系统提示词。“服务商代码”不要虚构成完整厂商列表，除非新增了真实数据来源。主按钮“测试并启用”，按真实响应展示成功/失败；绑定后只展示脱敏摘要，不回显完整密钥。

连接设备：展示设备名、平台、最近连接时间、连接状态；由连接器发起配对，App 扫码/输入信息后批准。禁止把交互方向画反。撤销绑定、撤销授权和撤销设备使用独立危险操作确认，明确影响对象。

必须区分三件事：**已绑定 / 设备连接 / 实际业务可用性**。当前类型里 `online`、`binding.enabled` 等字段不足以独立证明模型调用可用；缺少实测信息时显示“未验证”，不能造一个“模型健康”绿灯。

### 6.7 连接器配对 — `pages/pairing/scan.vue`

手机扫码为主，手动输入为辅；H5 摄像头不可用时明确提供手动方式。保留“配对标识”和“配对短码”两个必要字段，只有现有解析流程真实支持时才允许粘贴完整配对内容；不能把它们简化成单个 6 位码。**6 位确认码用于设备核对，不能代替查询短码。**

读取成功后进入确认页：设备名、平台、目标 AI、请求能力、到期时间；大字展示六位确认码，核对后允许批准。步骤：核对设备→在 App 批准→在连接器设备确认→完成凭据兑换。pending_local 要显示“等待设备端确认”，approved 要显示“等待设备完成连接”，redeemed 仅代表配对凭据已兑换，后续在线/业务验证仍独立。

expired / denied / cancelled 明确终止，提供重新发起说明。剩余时间由真实过期时间计算；模板不演示真实扫码，不伪造配对成功。

### 6.8 群设置 — `pages/group/settings.vue`

桌面抽屉、手机独立页。顶部群头像、名称、成员数；成员网格或清晰列表保留人类/AI身份和群主/管理员标签。常用操作只显示当前用户有权限执行的项。退出和解散分开，群主需要先转让或解散才可退出。普通成员不出现邀请/移除/改角色按钮。

历史起点如需自然时间展示，必须有真实数据或可核实映射；当前 `joined_seq` 不是时间，不能直接转换成“从某日可见”。缺少精确时间时使用“仅可查看本次加入后获授权的历史”。

**群邀请接收入口是明确的功能缺口**：可设计为联系人“申请”下的群邀请分组，或独立二级收件页；正式实现前需核实服务端查询、接收/拒绝接口及事件同步。这不是单纯换皮，本轮模板不模拟可用的邀请收件箱。

### 6.9 运行详情 — `pages/runs/detail.vue`

首先展示“哪个 AI 正在处理哪条请求”、状态、开始/结束时间和可用操作；原始 ID、attempt、generation 放“技术详情”折叠区。桌面由聊天状态条打开抽屉；手机进入详情页。

可以展示基于现有时间字段的状态摘要，不能编造未记录的工具时间线。失败摘要应脱敏；错误码可复制、默认次级展示。结果未知状态说明“执行结果尚不能确认，请核查后再发起”，避免主动引导盲目重试带来重复外部操作。当前运行详情页允许该状态重试而聊天页没有，实施前需要统一产品规则，并保留服务端权限判断。

### 6.10 我的 — `pages/me/me.vue`

顶部个人资料，下面三个分组：“AI 与设备”（我的 AI、连接设备）、“账号”（编辑资料、登录会话）、“高级”（服务器地址、版本）。退出置于底部独立区域。隐藏内部 API、WS、token 等术语，必要信息放帮助或折叠详情。

## 7. 状态与文案映射

| 数据状态 | 推荐文案 | 可见操作与边界 |
| --- | --- | --- |
| 发送请求未完成 | 发送中 | 不出现“已送达/已读” |
| 发送失败 | 未发送，点击重试 | 沿用原 client_message_id，不能重复造消息 |
| 持久 ACK 后 | 已发送 | ACK 不等于对方已读 |
| queued | 排队中 | 只有确有设备离线证据才写“等待设备上线” |
| dispatched | 已派发，等待执行 | 不提前写成运行中 |
| running | 正在处理 / 正在生成 | 可请求停止；没有可靠进度数据就不显示百分比 |
| cancel_requested | 已请求停止，等待确认 | 禁止立刻展示“已停止” |
| succeeded | 已完成 | 成功标记可折叠 |
| failed | 处理失败 | 查看原因；权限允许时发起新运行 |
| cancelled | 已停止 | 保留已有内容 |
| expired | 已超时 | 说明结果和后续操作 |
| recovery_required | 结果尚不能确认 | 引导核查，不自动重试或继续派发 |
| partial 且流中断 | 内容未完成 | 保留文本；根据运行终态显示原因 |
| 客户端实时连接断开 | 正在重新连接，消息状态稍后更新 | 不宣称 AI 离线；不虚构后台推送保证 |
| 无加载结果 | 加载失败，重试 | 不能把错误渲染为空列表 |
| 已撤权/已解散 | 已无法继续访问 / 群聊已解散 | 按授权清理缓存并停止增量，不能靠灰按钮替代权限检查 |
