# 可直接转交的 UI 改版任务

请基于现有 AIChat 项目重做网页和 Android 的 UI。先阅读本目录 `README.md`，再打开 `prototype.html` 查看布局和组件风格。模板使用虚构演示数据，只表达设计建议。请保持产品名 AIChat。

## 产品与已有技术

AIChat 是人类和 AI 拥有独立账号、联系人、私聊和群聊的应用。AI 可接模型 API，也可绑定外部 Agent 连接器；不要把产品改成单一 AI 问答页、AI 模型商城或后台仪表盘。

已有客户端位于 `apps/mobile`，使用 uni-app、Vue 3、TypeScript、Pinia；网页与 Android 共用此客户端。契约权威是 `contracts/PROTOCOL.md`；保留 API、store、WS 事件、授权、幂等、配对和运行状态语义。当前 Android 尚未完成真机验收。

## 视觉方向

采用安静、清晰、适合长时间聊天的风格：中性暖灰浅底、白色内容面、深墨色文字、少量青绿主色，AI 使用小面积紫灰身份标签。避免紫蓝大渐变、玻璃模糊、满屏卡片、夸张阴影和装饰性数据面板。浅色优先，深色复用语义 token。

正文 15–16px，聊天正文 16px、行高约 1.65；标题 22–24px。手机页边距 16px，常用圆角 10–12px，表面层级通过留白和微弱分隔建立。系统字体和统一线性图标；正式产品不用 emoji 拼导航。手机触摸区域至少 48px。rpx 需按平台验证，不能把 px 数值直接抄成同数值 rpx。

## 网页布局

桌面：72px 导航栏＋约 320px 会话列表＋弹性聊天区，聊天正文最大宽约 760px。导航包含会话、联系人、我的 AI，账号在底部。详情按需抽屉展开；窄屏收起为单页，绝不把三栏等比压小。消息区独立滚动，顶部和输入区固定。

## Android 布局

保留会话 / 联系人 / 我的三个一级 Tab，统一图标与文字选中态。我的 AI、连接设备放在我的页。聊天页使用返回导航和独立输入区，不显示一级 Tab。适配状态栏、手势区、软键盘和系统返回。

## 核心页面

1. **会话**：44–48px 头像，名称和时间在第一行，摘要和未读在第二行。AI 私聊有 AI 标签，群聊保留群身份。新建菜单支持现有私聊/建群。搜索只筛选已加载会话，不能假装全历史搜索。
2. **聊天**：自己消息浅青绿靠右；他人靠左。AI 回复有独立头像/名称/AI 标签；长回复轻量内容块，支持复制/引用。生成状态和停止入口可见，细节按需展开。不能虚构 token、费用、思考过程和工具轨迹。
3. **输入区**：群聊通过选择器选最多 3 个 AI，结构化 mentions；未选 AI 的消息只发到群。私聊 AI 可直接触发。网页 Enter 发送、Shift+Enter 换行并正确处理中文输入法；手机独立按钮发送。向上读历史时不能被流式消息强制滚到底部。
4. **联系人**：联系人 / 申请分段，人类/AI身份清楚；完整账号查找和本地筛选分开。建群用多选流程；“邀请已发送”不等于“已入群”。群邀请收件箱是现有缺口，需单列功能方案。
5. **我的 AI / AI 详情**：我的 AI 沿用 `scope=owned`，只展示我管理的 AI；获授权 AI 仍从联系人访问，不虚构新的列表查询来源。管理页只面向 owner，不能让非 owner 调用其授权清单接口。档案、接入、授权、设备分组。密钥仅在密码型表单输入，不回显。使用“服务商代码”，不能虚构厂商枚举。已绑定、设备在线、业务可用性分别显示，未知就写未验证。
6. **连接器配对**：连接器发起，App 扫码批准；手动方式保留配对标识和短码。六位确认码用于与设备核对，不是短码。批准后仍需设备端确认与兑换；不得直接显示模型可用。
7. **群设置**：展示成员身份、群主/管理员和按权限可用的操作，危险操作分区。历史可见时间不能从 seq 编造。
8. **运行详情**：优先展示请求摘要、AI、状态与操作，原始 ID 放折叠技术详情。九种 RunState 完整覆盖；取消请求被接收不等于已经停止。结果未知时引导核查，避免盲目重复执行。
9. **我的**：资料、AI 与设备、账号、高级设置分组。登录会话数量不能当作设备在线数量；高级服务器设置折叠。
10. **登录/注册**：保留账号密码和邀请码注册，字段标签清楚、错误就近显示；不加没有真实流程的第三方登录/找回密码。

## 必须遵守

- 不增删 API 契约，不破坏权限与幂等；发送失败重试沿用 client_message_id，Run 重试是新运行。
- 不把 UI 的灰按钮当作权限控制。保留 owner / 管理员 / 普通成员的边界。
- 不展示真实密钥、令牌或私聊数据；不在 UI 内常驻解释 WS、seq、generation 等内部术语。
- Markdown 是增强项；当前为文本，不自动启用原始 HTML。
- 空、加载、错误、失联、无权限、流式中断均要有设计；不能把失败当空列表。
- 不加入附件、语音、视频、公共商店、全局搜索、后台推送等未实现能力的可点击假入口。

若仅做设计，请交付桌面/手机关键页、组件与 token、全状态标注和可编辑源文件；若做代码，请先检查仓库指令并给出改动范围，再按上述边界实现。代码交付需附实际验证结果和未验收项，不能把模板演示视为 Android 已验收。
