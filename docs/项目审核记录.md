## 结论与部署边界

项目已具备本地验证过的身份、消息、AI 配对与 echo 连接器链路，但仍处于开发阶段。本轮修复多个会阻断登录、丢消息、重复发放凭据或绕过执行权限的问题。

用户明确要求先不部署，等待分配域名。本轮远端仅于 2026-10-25 通过 SSH 只读检查：目标为 `ubuntu@35.73.46.1`，已有 `~/aichat`、Docker/Compose 和 `/aichat/*` Caddy 路由，当时 AIChat 两个容器均停止。本轮没有启动容器、上传代码、修改 Caddy、写生产数据库、提交或推送 Git。该观察不能当作远端当前可用性证明。

`deploy/README.md` 原有 IP 修改得到保留；来源未确认的其他工作区文件不纳入本轮清理。

## 已修复的问题

| 问题及影响 | 实际修改 |
| --- | --- |
| 登录/刷新遗漏 account，客户端成功登录后立即退回登录页 | identity 返回协议要求的完整账号快照，并增加 HTTP 回归测试 |
| 邀请码、刷新凭据、配对兑换在并发请求下被重复消费 | 改为条件 UPDATE RETURNING；配对时串行化同一 AI 档案更新；真实并发回归验证只有一个成功者 |
| WSS 一次性票据修改未提交，可在另一会话重放 | 原子消费并在握手事务提交；人类票据消费时再检查登录状态 |
| 退出或刷新登录会话后旧 WSS 仍可读取事件 | 踢出旧 session 连接、提供关闭回调、接收与推送检查连接状态 |
| 连接器可提交其他连接器的 execution；迟到输出可改写已取消/终态运行 | 校验连接器身份、撤销状态和 execution 归属；按 conversation→run 加锁，检查 run/attempt 及 fence |
| 普通 AI 授权持有者可以查看无关会话的运行状态 | 读取权限限定为可见成员、触发者或 AI 所有者 |
| 原触发者已撤销 AI 使用授权，仍可人工 retry | 重试时重新检查原触发者的有效授权 |
| 模型 ProviderError 未提交，任务错误状态丢失 | 错误短事务明确提交；取消时丢弃尚未写入的缓冲 |
| 派发/运行租约未按租约时间回收，模型等待输出时没有续租 | 超时 attempt 失效，派发回收推进 fence；模型独立周期续租；续租失败与用户取消分开处理，保留未知结果状态 |
| 长会话首次历史查询取到最旧消息，分页丢失较新内容 | 数据库降序取最近一页，响应翻转为升序 |
| 消息事件是稀疏对象，客户端当作完整消息导致字段缺失 | created/updated 发完整 message DTO；事件授权比较兼容十进制字符串 seq |
| AI、联系人、成员、授权接口的客户端字段/路径与实际响应不一致 | 在 api 层统一转换线上的扁平 DTO；联系人申请提供方向与正确对方；修正授权删除路径 |
| 后台消息生成了局部缓存，第一次进入会话跳过历史快照 | 单独跟踪 snapshotLoaded，合并初始快照与实时事件 |
| HTTP 补拉过程中实时事件提前推进游标，历史事件被跳过；退出期间旧请求污染新账号 | 补拉时缓存实时事件并按序应用；连接/请求使用代次保护并清理旧缓冲 |
| 保存的 access_token 在重启后被当作全新有效令牌 | 启动时先用长期凭据刷新访问令牌；未传服务地址时读取已配对地址 |
| 本地先记成功、完成帧丢失后无法恢复 | 输出逐片持久化，保留 completion_pending；查询服务端后从 next_chunk_index 重放，确认终态后结束恢复 |
| 断线取消帧缺少 fence，输出片段发送后才检查上限，异常正文可能公开 | 补全取消公共字段；发送前检查 UTF-8 字节；公开错误使用固定文案 |
| ready 连接断开后仍显示在线 | ready/degraded/online 断线均回写 offline，避免覆盖仍在线的替代连接 |
| uni-app 预发布范围混装，H5 无法构建 | 固定同一套 uni-app 40209、Vue 3.4.21、Pinia 2.1.7，更新 package-lock |
| Compose 默认管理员密码且密码拼入 shell；生产可回退开发密钥 | 强制提供引导密码并从环境读取；生产校验 JWT/Fernet 配置；容器改非 root，增加健康检查和 init/exec 启动 |

## 尚未完成与上线前条件

1. **群邀请接收界面缺失。** 后端有审批接口，但客户端没有让被邀人发现并接受邀请的完整界面；多人群聊不能宣告端到端产品验收完成。
2. **依赖告警未清零。** 2026-10-25 对锁文件运行 `npm audit --omit=dev --registry=https://registry.npmjs.org --json`，报告 20 个受影响依赖节点（17 high、2 moderate、1 low，0 critical）。其中含 uni-app 传递引入的构建、SSR/i18n 组件，不能等同于应用有 20 个可利用漏洞。需要针对最终分发平台核对可达性并评估整套 uni-app/Vue 升级；未运行 `audit fix --force`。Python 依赖和镜像也尚未做完整供应链漏洞审计或版本锁定。
3. **真实模型和设备未验收。** echo 与假模型流通过，不代表 Hermes/Codex/ZCode 或真实供应商已连接；Android、相机扫码、前后台和弱网需真机验证。
4. **单进程约束。** 当前 API 自带所有后台循环，独立 worker 入口存在实时 hub 分离问题。先使用单 uvicorn worker；拆进程、多实例需要另行实现和验证。
5. **生产数据层未验收。** 还需真实 Docker 镜像构建、PostgreSQL 迁移及并发验证、容器重启、数据库与主密钥分别备份及恢复演练。
6. **域名与 HTTPS 待安排。** 当前没有本轮新增上线入口。用户确认域名后再核对 DNS、TLS、WSS、反代路由和实际访问流程，并保持同机其他服务不受影响。

最初审核修复与本地验证已完成；后续已按新授权完成基础上线，当前部署结果见文首更新。群邀请接收 UI、真实供应商、真机和依赖告警等缺口仍保留。
