# AIChat 产品需求

日期：2026-10-24。状态：初期设计稿；“建议”表示本次设计采用的默认值，并非用户已经逐项确认。

## 1. 产品定位

以聊天软件的交互承载人类与 AI 的交流。用户能添加一个 AI 为联系人，向它单独提问，也能建立包含多人和多个 AI 的群聊。AI 有固定身份，能显示自己的消息和执行状态。

微信作为联系人、会话与群成员操作的交互参考。首版不复制朋友圈、支付、公众号等体系，不依赖微信账号、微信客户端或微信机器人网关。

AIChat 拥有账号、权限、会话和消息事实。外部 Agent 拥有自己的执行环境与工具。群聊路由由 AIChat 负责，不要求 Hermes 充当唯一总控，也不把 AgentForge 已经存在作为前提。

## 2. 首版范围与使用对象

建议首版为封闭使用的 Android MVP：管理员可邀请多个真实用户，每个用户有独立账号；个人使用只是最小部署情况，不把数据结构限制成单用户。

| 首版包含 | 后续扩展 |
| --- | --- |
| 邀请注册、登录、退出、资料与设备会话管理 | 公开注册、第三方登录、组织与企业管理 |
| 人类账号、AI 账号、联系人申请及移除 | 公开 AI 市场、公开群搜索、跨服务器联邦 |
| 人与人、人与 AI 私聊；多人和 AI 混合群聊 | 语音视频通话、朋友圈、支付 |
| 文本、Markdown 展示、引用、结构化 @、聊天历史与未读 | 图片、文件、语音及多模态输入 |
| 模型 API 接入与一个真实外部 Agent 连接器 | 所有指定厂商的完整适配、连接器集群 |
| AI 流式回复、停止、显式重试、离线/失败提示 | 自主多轮讨论、自动委派、复杂工作流 |
| 用户停留前台时实时收发，恢复前台后补齐消息 | 厂商推送、后台到达率保证与多端同步优化 |

用户提出的所有 AI 接入方向保留在目标设计中，但首版验收只要求“一种模型 API + 一个真实外部 Agent”贯通，两条通路都必须验证，不用模拟器代替全部真实接入。

## 3. 账号模型

### 3.1 共同身份

人类和 AI 共用账号主键、唯一账号名、昵称、头像、简介、账号类型与状态。昵称可以重复，账号名不能重复；@ 与授权始终按不可变账号 ID 处理。

| 对象 | 登录/接入方式 | 主要职责 |
| --- | --- | --- |
| 人类账号 | 首版建议邀请注册 + 用户名密码 | 发消息、维护联系人、建群、管理自己拥有的 AI |
| AI 账号 | 所有者创建资料，运行绑定使用受限服务身份 | 在授权会话内接收任务并以自身身份回复 |
| AI 所有者 | 普通人类账号的一项资源关系 | 配置 AI、选择运行方式、授权他人使用、停用或撤销连接器 |
| 平台管理员 | 独立管理权限 | 邀请用户、停用违规账号、维护服务；不默认进入他人会话 |

AI 没有共享的人类密码。模型 API 的密钥、AIChat 登录凭据与外部 Agent 原有登录是三种不同凭据。

同一模型可以支撑多个 AI 账号，如“代码助手”和“写作助手”；同一个 AI 可以替换底层模型或连接器，身份和会话继续保留。首版每个 AI 同时只有一个启用的运行绑定。

首版不支持 AI 转移所有权与共同所有者，避免身份、历史和凭据归属不清。

### 3.2 联系人与 AI 使用授权

- 人类按账号名精确搜索、发送申请，对方接受后成为联系人；首版无全站模糊人员目录。
- 所有者创建 AI 后自动成为该 AI 的联系人。
- AI 资料码与连接器配对码是不同类型：资料码用于申请联系/发起私聊；配对码用于绑定执行器。
- 其他人向 AI 申请联系时由其所有者批准，同时建立 AI 使用授权；AI 不自行批准联系人。
- 移除联系人阻止新的私聊发送，已有历史按会话访问规则保留；不会自动踢出共同群聊。
- 拉黑按账号方向生效，阻止该账号私聊及向该用户发起邀请；共同群内是否屏蔽展示是后续功能，首版提示可退群。

AI 使用授权首版仅有“所有者本人可用”或“指定人类账号可用”。没有“所有注册用户都能用”的默认值。

## 4. 私聊

联系人可发起人类—人类或人类—AI 私聊。同一无序账号对只存在一个有效私聊，重复打开返回原会话。人类—AI 私聊中，每条普通用户消息触发一次回复，无需 @。

AI—AI 独立私聊不纳入首版；多个 AI 的协作在有人类成员的群中进行。

消息展示发送者、服务端时间、发送中/已发送/失败；“已发送”只表示服务端已持久化，不表示对方读过或 AI 已执行。人类已读以显式阅读游标计算；AI 采用“等待/运行/完成”状态，不伪装成人类已读。

点击重发同一条发送失败的消息沿用原请求 ID，避免重复记录；点击“让 AI 重新回答”创建新的运行并保留旧结果。

## 5. 群聊

### 5.1 创建与成员

建议首版由人类创建群，选择已有联系人；AI 通过其所有者的授权加入。角色分为群主、管理员、普通成员，AI 不可担任群主或管理员。

首版邀请人类成员需要对方接受。邀请 AI 时，邀请者必须是群主/管理员，且 AI 所有者仍在群中并确认本次加入；所有者也是邀请者时直接确认。联系人授权并不自动允许将 AI 拉入任意群。

群成员看到新增 AI 的身份、所有者，以及“后续发给该 AI 的内容会发送至其外部模型/执行器”的提示。首版新成员和新加入 AI 默认不获得加入前的消息。

| 操作 | 权限与效果 |
| --- | --- |
| 修改群名、邀请、移除成员、设置 AI 回复策略 | 群主/管理员；不能越过 AI 所有者的执行授权 |
| 任命管理员、转让群主、解散群 | 群主；转让对象必须是当前人类成员 |
| 退出群 | 普通成员/管理员可退出；群主先转让或解散 |
| AI 所有者退群或被移除 | 其在群内的 AI 同时移除；取消在途任务并使结果失效 |
| 解散群 | 归档会话，拒绝新消息与任务；原成员保留解散前可见历史 |

退群/被移除之后不再获得新内容；其历史访问上限固定在离开时。重新入群形成新的成员区间，默认看不到离开期间内容。

### 5.2 AI 触发规则

首版默认采用**人类显式 @**，避免所有 AI 对每条群消息都抢答。

| 触发 | 行为 |
| --- | --- |
| 人类消息 @ 一个 AI | 创建一个回复任务 |
| 人类消息 @ 多个 AI | 各创建一个任务，同属一个触发批次；并行执行，不互读尚未完成的结果 |
| 人类引用 AI 消息但不 @ | 只产生引用关系，不自动触发 |
| 群内普通人类消息无 @ | 保存并广播，不触发 AI |
| AI 回复中出现 @ 或“请其他 AI 接着说” | 首版只展示，不创建下游任务 |
| 人类希望 AI 接着讨论 | 新发消息并显式 @，可引用之前结果 |

首版不开放 @全体AI、一句话无限转发或模型自行决定谁必须执行。后续协作模式必须引入轮次、预算、发言次数与停止条件后再开启。

被触发的 AI 接收当前触发消息和允许范围内的最近上下文；上下文在任务创建时固定，不因后来新消息静默变化。若多个 AI 使用同一运行绑定，首版每个 AI 串行执行，其他任务排队，避免 CLI 会话混杂。

## 6. 接入体验

### 6.1 模型 API

所有者创建 AI 资料，选择模型供应商配置，录入受保护的模型凭据，选择模型和能力；连接测试成功才启用。首版建议只支持管理员预配置的服务地址，用户不能任意输入内网或云元数据地址。

该路径不要求额外 CLI，也不要求扫码。后端保管密钥并执行调用，聊天客户端只获得脱敏配置。模型调用额度默认由 AI 所有者承担，配置每用户/AI/运行预算；无法准确获知费用时显示未知，不展示虚构费用。

### 6.2 外部 Agent

连接器在用户的 Windows 或 VPS 上运行，申请短期配对并展示二维码。用户在 App 扫码、核对连接器信息与确认码、选择自己的 AI 账号并授予能力；连接器取得受限凭据后上线。

连接器首次绑定需其本机操作者再次确认配对，防止陌生人抢扫公开终端的二维码。手机也可以输入配对码；同机使用不强迫用户用摄像头扫描本机屏幕。

使用者可以看到在线状态、运行方式与实际能力。连接器在线不等于其模型可用；模型额度、登录过期、运行超时分别显示原因。

## 7. 页面职责

以下为信息架构，未制作或实现 UI 原型。

| 入口 | 核心内容 |
| --- | --- |
| 会话 | 私聊/群聊列表、最后消息、未读数、进入聊天 |
| 联系人 | 人类与 AI 标识、申请、精确查找、建群 |
| 我的 | 本人资料、我的 AI、登录设备、设置 |
| 我的 AI / AI 详情 | 所有权、运行方式、能力、使用授权、绑定/撤销 |
| 聊天页 | 消息、引用、@ 选择、AI 输出、停止、失败与重试 |
| 群设置 | 成员、角色、AI 所有者、回复策略、退群/解散 |
| 扫码确认 | 连接器身份、目标 AI、请求能力、确认码、授权与拒绝 |
| 运行详情 | 对应消息、阶段、耗时、允许公开的工具摘要、失败原因 |

首版运行详情是聊天的附属页，不单独开发完整项目看板。工具调用日志与推理内部过程不自动发布为聊天内容。

## 8. 执行与权限边界

首版所有可用接入必须至少支持文本聊天。对实际外部 Agent，默认禁用文件写入、命令执行和其他外部副作用；只能选择能限制这些能力的适配方式，否则不得作为首版普通聊天接入启用。

后续执行型能力由所有者配置工作目录和允许工具；每次高影响动作再绑定到明确运行的批准请求。群成员能 @AI，不代表能操作 AI 所有者电脑。首版的“停止”是尽力取消，在停止确认前不承诺外部进程已退出。

后端需要处理消息与上下文，因此本设计不提供端到端加密承诺。用户须知道获授权的外部运行方会接触发给它的上下文。

## 9. 成功标准

两个隔离的人类账号能互加联系人并私聊；一个模型 AI 和一个真实连接器 AI 有独立资料，能分别私聊并加入同一群。@ 指定 AI 后只触发目标；消息可恢复，重复发送不重复执行，移除成员和撤销连接器会即时收回能力。

完整验收用例见 [设计决策与验收](设计决策与验收.md)。上述均为后续目标，当前未开发或业务验收。
