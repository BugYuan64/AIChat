# 数据模型

## 模型地位与共用规则

本文定义一期必要逻辑表、约束和事务，不是已执行数据库迁移。数据库默认 PostgreSQL。
权限规则见[账号与权限](账号与权限.md)，字段与状态解释分别以[消息契约](消息与HTTP-WSS契约.md)和[Connector](统一AI接入.md)为准。
内部主键默认 UUID，示例协议使用不透明字符串；时间用 UTC，seq/cursor/revision 用 bigint，线上序列化十进制字符串。
下表省略普遍存在的 created_at/updated_at；所有 FK 删除默认 RESTRICT，删除业务对象不连带抹去审计或未知任务。
需要保留内容时采用禁用/撤销/closed；正式删除、匿名化和保留期限在上线前明确并验证。

## 身份与设备逻辑表

| 表 | 最小字段与关系 | 约束/索引 |
| --- | --- | --- |
| account | account_id、kind、display_name、status、version | PK account_id；kind=human/agent；status=active/disabled |
| agent | agent_id FK account、owner_id FK account、adapter_kind、status、policy_version、capability_policy | PK agent_id；UNIQUE(agent_id,owner_id)；owner_id 索引 |
| runner | runner_id、agent_id、owner_id、name、device_fingerprint、status、connection_epoch、last_seen_at | 复合 FK(agent_id,owner_id)→agent；索引(agent_id,status) |
| credential | credential_id、runner_id FK、secret_hash、version、scopes、expires_at、revoked_at | 仅摘要；UNIQUE(runner_id,version)；每 runner 最多一条有效凭据 |
| pairing | pairing_id、agent_id、owner_id、device_summary、requested/granted_capabilities、public_reference_hash、user_code_hash、device_code_hash、status、version、expires_at、consumed_at、runner_id | 复合 FK→agent；三个码的有效查找值唯一；按 expires_at 清理 |
| session | session_id、human_account_id FK、refresh_hash、refresh_version、device_summary、expires_at、revoked_at | 仅 human；索引(human_account_id,revoked_at)；轮换旧摘要失效 |
| ws_ticket | ticket_id、ticket_hash、session_id FK、audience、expires_at、consumed_at | 摘要唯一，原子消费，一次性短期握手 |
| runtime_session | runtime_session_id、agent_id FK、conversation_id FK、membership_id FK、conversation_auth_version、adapter_kind、upstream_reference_summary、version | UNIQUE(agent_id,conversation_id,membership_id,version)；auth_version 变化即作废旧映射；不存厂商密钥 |

account 的 agent 子型必须有 agent 行，owner/session 主体必须是 human；实现时以事务及可验证约束触发器防止跨表子型不一致。
agent.status=unbound/active/disabled；account.status 是统一禁用开关，两者均须允许才可调度。
credential 不存真实 token、密钥或可还原密文；服务端保护材料独立部署在密钥管理边界内。
pairing 不存二维码秘密明文；user_code 有效期内的冲突重新生成，过期/消费后禁止兑换。
runner 行在首次消费时创建，pairing.runner_id 此前为空；credential 一次明文签发和消费状态同事务提交。
session 是 human 登录会话，runtime_session 是上游会话隔离映射，两者不可互当凭据或授权。
runtime_session 同时约束 native 会话、持久记忆、摘要、工具输出与工作区作用域；conversation_auth_version 变化时必须停用旧映射与旧上下文，不复用旧私密内容，adapter 无法强制这些作用域时禁止启用跨会话共享模式。

## 联系人、会话与成员

| 表 | 最小字段与关系 | 约束/索引 |
| --- | --- | --- |
| contact | contact_id、low_account_id/high_account_id FK、requester_id FK、status、blocked_by、version | UNIQUE(low_account_id,high_account_id)，low<high；双方索引 |
| conversation | conversation_id、kind、title、creator_id FK、owner_member_id、direct_low_id/direct_high_id FK、last_seq、auth_version、status | direct 双人键部分唯一；kind=direct/group；status=active/closed |
| invitation | invitation_id、conversation_id FK、target_account_id FK、inviter_id FK、admin_approved_by、target_approved_by、status、expires_at、version | 每会话+目标最多一条 pending；状态/过期索引 |
| member | membership_id、conversation_id FK、account_id FK、role、visible_from_seq、left_seq、joined_at、left_at | 每会话+账号最多一条 active；索引(conversation_id,account_id,left_at) |
| read_cursor | conversation_id FK、account_id FK、membership_id FK、read_seq | PK(conversation_id,account_id,membership_id)，单调且在可见边界内 |
| delivery_receipt | conversation_id FK、session_id FK、membership_id FK、delivered_seq | PK(conversation_id,session_id,membership_id)，独立于 read_cursor |

contact.status=pending/accepted/rejected/blocked；同一关系的重新申请按版本更新，不新建可绕过 blocked 的记录。
conversation direct 必须有规范化两个账号 ID，group 的 direct 双人键必须为空；direct 双方不可修改。
member.role=owner/admin/member，仅 group 使用 owner/admin，且必须是 human；direct 的两人均为 member。
活跃群必须至少一个 active human、恰一个 owner，owner_member_id 必须指向本群 active human member。
此类跨行条件由会话锁下的事务与延迟校验保障，不能伪装成普通单行 CHECK 就能完成。
member.active 以 left_at 为空判定，不再另维护容易漂移的 status；visible_from_seq 包含加入系统消息。
退群把 left_seq 记为当时 last_seq，仅用于审计，退群后读接口不因这个旧边界继续授权。
重新加入产生新的 membership_id，新区间不与旧授权自动合并；read_cursor/receipt 同样重新开始。
invitation.status=pending/accepted/rejected/expired/revoked；接受时才激活成员，两项批准依据需保留。

## 消息、任务和执行记录

| 表 | 最小字段与关系 | 约束/索引 |
| --- | --- | --- |
| message | message_id、conversation_id FK、seq、sender_account_id FK、sender_membership_id FK、kind、text、mentions、client_message_id、reply_to_message_id FK、run_id、trigger_message_id FK、status、terminal_reason、revision、last_delta_seq | UNIQUE(conversation_id,seq)；human 幂等键部分唯一；索引(conversation_id,seq DESC) |
| message_delta | attempt_id FK、delta_seq、message_id FK、text、content_hash、expires_at | PK(attempt_id,delta_seq)；片段短期保留，聚合文本长期权威 |
| run | run_id、conversation_id FK、trigger_message_id FK、requester_account_id FK、requester_membership_id FK、agent_id FK、agent_membership_id FK、response_message_id FK、state、available_at、queue_deadline_at、deadline_at、lease_until、current_attempt_id、fencing_epoch、policy_version、policy_snapshot、chain_id、parent_run_id FK、round | 根 run UNIQUE(trigger_message_id,agent_id)；response_message_id 唯一；队列索引(state,available_at) |
| run_attempt | attempt_id、run_id FK、attempt_no、runner_id FK、connection_epoch、fencing_epoch、state、acked_at、started_at、lease_until、finished_at、last_delta_seq、side_effect_status | UNIQUE(run_id,attempt_no)、UNIQUE(run_id,fencing_epoch)；租约过期索引 |
| operation_receipt | attempt_id FK、type、operation_id、request_hash、result_summary | UNIQUE(attempt_id,type,operation_id)；同 type 同 ID 重试复用回执，不同 type 不得共用 ID |
| approval | approval_id、run_id FK、attempt_id FK、fencing_epoch、action_digest、summary、resource_owner_id FK、policy_version、decision、expires_at、used_at | 同 attempt+action_digest 至多一个有效批准；执行前按同一摘要核对并原子置 used_at，重复消费拒绝；不存秘密参数 |
| collaboration_chain | chain_id、conversation_id FK、authorizer_id FK、policy_version、state、max_rounds、max_concurrency、budget_total、budget_reserved、budget_used、deadline_at | chain 行锁下预留额度；非负且不超上限 |

message 的 human 幂等键为 conversation_id+sender_account_id+client_message_id，正文/mentions/reply 摘要存于去重比较范围。
AI message.run_id 部分唯一，run.response_message_id 反向唯一；response 在 start 时创建，避免 queued 就出现假回答。
message 与 trigger/reply、run 与 trigger/response 的跨会话关联，用 composite FK 或事务内同会话校验并验证，不能只检查 ID 存在。
message.status=draft/partial/final；terminal_reason 为空/cancel/error/unknown，终止空 draft 与终止 partial 都保留关联 run 状态。
text 消息须有合法 sender_account_id 与 sender_membership_id；system 两字段为空，由平台写入，不新增第三种 account.kind。
run/attempt 状态枚举严格沿用 Connector；run 自身承担持久队列，不另复制一张内存调度真相。
一期以 active run 的 agent_id 部分唯一约束保证 agent 并发 1，active 指 leased/running/cancel_requested；放宽并发前须改为受锁保护的容量预留。
agent.policy_version 是 owner 配置修订号，run.policy_version 是包含全部授权修订的有效快照标识，policy_snapshot 保存其非秘密执行约束。
current_attempt_id 指向本 run 的 attempt；fencing_epoch 只增不减，回报必须匹配当前有效 attempt 和 runner。
side_effect_status=none/confirmed/unknown，unknown 不可被通用自动重试策略当作安全失败。
子 run 用 parent_run_id+agent_id+round 的唯一键去重；一期未开启协作时不生成 collaboration_chain。

## 事件、投递与审计

| 表 | 最小字段与关系 | 约束/索引 |
| --- | --- | --- |
| outbox | event_id、aggregate_type/id、conversation_id、auth_version、type、payload_reference、occurred_at、fanout_state、lease_until | 同业务状态事务写；待处理/租约索引，按 event_id 幂等 |
| event_stream | account_id FK、last_cursor | 每 human 一行，锁内分配主体 cursor |
| recipient_event | account_id FK、cursor、event_id FK outbox、expires_at | PK(account_id,cursor)，UNIQUE(account_id,event_id)；主体+过期索引 |
| sync_snapshot | snapshot_id、account_id FK、session_id FK、snapshot_cursor、snapshot_data、expires_at | 一致性读物化，默认 5 分钟失效，分页再次过滤撤权内容 |
| audit_event | audit_id、actor_account_id、actor_runner_id、action、object_type/id、request_id、safe_summary、occurred_at | 对象/时间索引；主体二选一或平台系统，不记录秘密 |

outbox 只存可重新授权解析的引用/摘要，不把群正文复制进 owner 通知；delta 可在授权后读取短期片段。
fanout 基于提交时成员及区间生成候选接收者，投递/补拉仍查当前权限，不能只信候选列表。
对刚移除的主体另投只含其自身 membership 撤销的墓碑，禁止混入群正文或其他成员资料。
recipient_event 分配必须复用 account_id+event_id 唯一键，worker 崩溃后不能为同事件分配第二个 cursor。
删除不可见内容也允许 next_cursor 前进；事件过期默认 7 天，message_delta 默认 24 小时，过期片段以 message 快照恢复。
只有 fanout 已完成且全部必要投递引用过期后才清理对应 outbox；message 删除与事件清理分开，不串联删除审计。
audit 的 actor 也可为平台系统，系统自动取消仍关联原触发者及原因，避免伪装为 human 主动操作。

## 关键事务与竞态

| 用例 | 同事务工作 | 必查不变量 |
| --- | --- | --- |
| 并发建 direct | 检查 contact/账号，规范化双人键，插会话及双方 member | 唯一冲突取原会话，再按当前权限返回，不建第二个 |
| 发 human 消息 | 锁 conversation，查身份/成员/幂等键，增 seq，写 message、queued run 与 outbox | 不信 sender；同键不同内容冲突；不创建未获准目标 run |
| 成员加入/移除 | 锁 conversation，查邀请/角色，更新 member、auth_version、系统消息与 outbox | 加入边界精确；移除触发在途 run 停止；群主及 human 数约束 |
| 首次配对消费 | 按 agent→pairing 锁定，查状态/owner/策略/过期，写 runner、credential 摘要、consumed 与 audit | 单次消费；同一事务中的明文仅用于唯一成功响应 |
| 领取 run | 锁候选 run，可用 SKIP LOCKED；复查账号/成员，增 epoch、插 attempt、写 leased | 同 run 仅一条当前租约，不跨 runner 领同一 attempt |
| 批准 start | 锁 conversation 后锁 run/attempt，复查授权/租约，写 running，预留响应 message 及 seq/outbox | 旧 fence 不能开工，响应 message 只有一个 |
| 接收 delta | 同样锁序，校验当前 attempt/epoch/权限/连续序号，写片段、更新聚合/版本与 outbox | 重片不追加，缺片不跳过，终态不再接收正文 |
| 终结 run | 锁 conversation→run→attempt→message，校验幂等回执及 fence，写终态/最终文本/outbox | 取消中不得成功复活，迟到结果只安全审计 |
| 派生协作 | 按 conversation→chain 锁定，复查策略/成员，预留预算并插子 run/outbox | 不超轮次/并发/额度，重复建议不再扣预算 |

统一锁序为 conversation→chain（如有）→run→attempt→message；配对独立使用 agent→pairing→runner→credential。
direct 已存在时，阻止联系人和发送均先锁该 conversation 再查/改 contact；尚无 direct 时创建和阻止通过 contact 锁串行化。
创建事务持 contact 锁时不反向等待既有 conversation 的锁，唯一键冲突后释放事务并重新鉴权返回既有会话。
领取 worker 只在短事务中锁 run 并标 leased，不反向等待 conversation；真正启动另起遵循统一锁序的事务。
若领取时的权限预检与成员移除交错，start 的锁内复查必须阻止执行；领取成功不构成工具授权。
成员变更在同一事务标 cancel_requested 或取消 queued，并写取消 outbox，不能等通知发成功才撤权。
对外通信、上游 CLI 调用和等待人类审批都放在事务之外，禁止长时间持数据库锁。
事务提交后响应丢失按幂等键返回既有结果，但仍先验证调用者现在是否有权看到正文。

## 故障恢复与待实现验证

outbox worker 持短租约，恢复后重投，业务端与 recipient_event 双层去重，不承诺网络恰好一次。
run leased 且未批准 start 可以新 attempt 回收；running 无法确认结果时进入 unknown，旧 epoch 永不重新获得提交权。
unknown 仅接受人工核对审计和关联新 run，不由迟到 finish 自动改 succeeded。
审批过期、策略变化、成员撤权及凭据轮换使未执行批准失效；运行时须再次校验，不把批准永久缓存。
read_cursor 单调更新需绑定本次 membership，避免退群后新加入继承不应可见的读位置。
备份包含 message、member、run、outbox 和审计的一致快照；恢复后先停调度、失效旧连接与租约，再人工核对未知操作。
实现阶段需并发验证唯一键、锁顺序、事务回滚、恢复及越权查询，本轮未建表、迁移或运行数据库测试。
