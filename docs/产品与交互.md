# 产品与交互

## 定位、角色与范围

本文是用户流程和页面状态的权威说明；技术默认见[设计决策与验收](设计决策与验收.md)。所有页面和功能待实现。
AIChat 是独立 App，参考微信的会话、联系人和群交互，不嵌入或修改微信客户端。
human 是人类账号；agent 是有独立平台身份的 AI 实例；owner 是管理该实例的 human。
同一 human 可管理多个不同或同厂商 agent，但每个 agent 保持独立资料、会话与运行上下文。
平台账号与模型厂商账号不同，扫码绑定的是本平台 runner，不是厂商登录。

| 优先级 | 用户能力 | 边界 |
| --- | --- | --- |
| Android MVP | human-human、human-agent 私聊，含 AI 的多人群 | 每个会话至少一个 human，不强制加 AI |
| Android MVP | 联系人、成员角色、历史、扫码、任务状态和审批 | 首期文本，AI 和客户端可离线 |
| MVP 后 | 有限协作、H5、小程序 | 协作显式开启，多端逐一适配 |
| 保留模型 | AI-AI 私聊、纯 AI 群、附件、iOS | 不纳入一期，不承诺交付日期 |

成功标准是用户能知道“谁在说话、谁可以看到、任务执行到哪、如何停止”，而不只是看到一段 AI 输出。

## 信息架构

```text
登录后
├── 会话列表 → 私聊 / 群聊 → 消息详情 / 任务详情
│                         └→ 群设置 → 成员 / 邀请 / 协作策略
├── 联系人 → human / agent 资料 → 发起私聊 / 联系申请
├── 接入管理 → 我的 Agent → runner / 能力 / 撤销 / 轮换
│                        └→ 扫码批准 / 手动配对码
├── 待审批 → AI 入群同意 / 设备绑定 / 工具操作
└── 账号设置 → 会话设备 / 隐私 / 退出
```

| 页面 | 必须显示 | 操作与权限 |
| --- | --- | --- |
| 会话列表 | 名称、最后消息摘要、未读、断线标记 | 打开、按授权同步，不泄漏已移除群摘要 |
| 联系人 | human/agent 标签、申请与阻止状态 | 建联需同意，不能靠账号枚举批量发现 |
| 聊天 | 发送者身份、时间、消息状态、@目标、任务卡片 | 人类消息重试沿用同一 client_message_id |
| 群设置 | 群主、管理员、成员、历史起点、AI 运行设备归属 | 按角色显示邀请、移除、转让及退出 |
| Agent 资料 | 名称、owner、adapter、在线与业务可用状态 | 发起授权私聊，owner 才能管理设备 |
| 接入管理 | 配对阶段、设备指纹摘要、权限、最后连接 | 明确批准、拒绝、撤销与重新配对 |
| 任务详情 | queued/运行/取消中/终态、关联消息、工具审批 | 发起者取消自己的任务，管理者可紧急停止 |
| 账号设置 | 当前 human、登录设备、会话撤销入口 | 不展示 runner 或厂商秘密 |

## 文字线框

```text
[群名] [连接恢复中]                              [群设置]
成员：2 human / 2 agent       历史可见：本次入群起
human甲：@助手A 请总结这段讨论
任务卡：已持久接收 → 等待设备 → 运行中            [取消]
助手A：生成中的内容……                         [未完成]
[输入文本] [选择 @对象]                            [发送]
```

文本里的“@助手A”必须由选择成员形成结构化 mentions 才构成调度目标，普通同名文字不触发。
渲染 AI 文本时保留身份标签；文本、链接、Markdown 和工具结果都视为不可信输入，不自动执行。

## 关键流程

1. human 登录并与另一 human 建联，创建私聊；双方接受后可正常发收，不需要 AI。
2. human 创建 agent 资料，在设备启动 runner 请求配对；手机扫描或输入短码，核对设备和权限后批准。
3. 配对后分别显示“平台已绑定”“runner 在线”“adapter 业务验收状态”，不合并成一个绿灯。
4. human 与自己的或已获准联系的 agent 建私聊，发送文本，收到持久 ACK 和任务状态。
5. 建群时邀请 human；加入 AI 需群管理许可与该 AI owner 同意，入群后只见本次加入起的历史。
6. 群内 human @特定 AI 触发 run；无 @ 的消息仍保存和分发给人类，默认不调度 AI。
7. AI 离线时文本仍成功持久化，任务显示等待设备；超出排队时限变成失败，不冒充 AI 回复。
8. 人类取消时先显示“取消请求已接收”，收到停止确认才显示取消成功；不能确认则显示结果未知。

同一消息可 @多个有权限的 AI，各产生独立 run 和响应 message；一期上限见[设计默认](设计决策与验收.md)。
AI 发出的 @ 默认只是文本/引用，不触发下一 run。有限协作改由平台校验策略和预算后派生任务。
审批卡片显示操作类型、目标资源、最小参数摘要、有效期和审批主体，不让 AI 自己点击同意。

## 状态与异常反馈

| 状态 | 用户可见行为 | 恢复方式 |
| --- | --- | --- |
| 空会话/无联系人 | 说明可建联/建群/绑定，不显示虚构历史 | 提供相应创建入口 |
| 加载与分页 | 显示加载状态，保留已授权快照 | 失败后沿用分页标记重试 |
| App 离线 | 草稿留本地，未取得持久 ACK 标为待发送 | 恢复后按同一幂等键查询或重发 |
| runner 离线 | 消息已接收与任务等待设备分开展示 | 排队截止前自动等候，超时后人类选择新任务 |
| 流式中断 | 保留 partial，标明不是完整答案 | 拉取快照及任务终态 |
| 已被移除/账号禁用 | 停止发送与增量，清理可控缓存 | 不用旧游标继续读，重新加入需新授权 |
| 配对过期/拒绝 | 明确没有设备绑定成功 | 从新 pairing 开始，不复用旧二维码 |
| 工具不支持审批/隔离 | 显示能力不可用，禁用高风险操作 | 更换可验证 adapter，不能靠提示词解锁 |

服务端已撤权不能抹去对方已保存的截图或副本；客户端清缓存是隐私措施，不是服务端授权替代品。
历史访问规则详见[账号与权限](账号与权限.md)，消息状态详见[消息契约](消息与HTTP-WSS契约.md)。

## 多端与通知

Android 一期验证扫码、键盘、滚动、断网、后台恢复和安全存储；iOS 不在一期承诺。
H5 提供无扫码摄像头时的手动配对码，重新验证存储、Origin 和浏览器连接限制。
小程序重新核对平台网络、域名、生命周期、通知和发布要求，不认为复用框架就无需适配。
后台通知需要独立服务与系统权限验证，WSS 在线只表示当前连接状态。
本轮不引用未经核对的法律结论；上游事实来源集中在[来源章节](设计决策与验收.md#sources)。
