# AIChat 全客户端 UI 重设计

日期：2026-10-27  
状态：待用户批准；批准前不修改产品代码

## 1. 意图与原因

AIChat 当前十个页面已经具备主要业务能力，但界面仍以通用卡片、文字按钮和纵向手机列表为主：桌面 H5 像被拉宽的手机页，页面之间缺少稳定的视觉骨架，图标、焦点、错误反馈与状态表达不成体系，动效多为一次性淡入，无法帮助用户理解“正在连接、生成、等待、切换和完成”等状态。

本次改版要在不改变 API、权限、协议和业务语义的前提下，建立一套适用于 H5、Android 和微信小程序的统一界面语言。视觉参考来自用户提供的 BentoML 薄荷绿／深墨／紫色截图、Nimbus 青色品牌感、shadcn-vue 的组件层级与交互规范、Lucide/Iconify 的线性图标体系，以及 `apc.wsnbb.shop/management.html` 的错峰入场和状态动效。

本文是本轮 UI 实施的视觉与交互权威。`docs/ui-redesign/` 中的旧交接稿继续作为业务边界和历史设计参考；与当前源码或本文冲突时，以当前源码的真实能力和本文为准，不沿用旧稿的深色主题、旧断点或过时状态描述。

## 2. 范围

覆盖 `apps/mobile` 的全部十个页面：

1. 登录／邀请注册／服务器设置
2. 会话列表
3. 联系人／申请／建群
4. 聊天
5. 我的
6. 我的 AI
7. AI 详情／接入管理
8. 群设置
9. 连接器配对
10. 运行详情

同时调整这些页面共同依赖的设计 token、基础组件、H5 桌面壳层、图标资源、动效工具和必要的表单／验证辅助函数。

## 3. 目标

- 建立统一、可复用且跨端可编译的设计系统，不再让每页自行拼接卡片、按钮和状态。
- 让 H5 在桌面宽度下成为真正的工作台布局，移动端继续保持自然的单页导航。
- 配色从单一深绿块升级为“暖白／薄荷绿／深墨＋少量紫色与青色身份色”，同时保证文字、焦点和控件边界可辨识。
- 用动效表达进入、切换、加载、生成、连接、成功、失败和抽屉层级；装饰动效克制，不妨碍阅读。
- 修复评测 A01—A10：键盘操作、可访问名称、持久错误、自动填充、恢复说明、占位文字对比、44px 溢出、登录文案、动态标题和 Vue Router 警告。
- 保留现有请求、幂等、权限、WSS 恢复、任务状态和配对流程，不用视觉改版暗示未实现能力。
- 为触屏提供至少 44 CSS px 的交互目标，并支持清晰的键盘焦点。
- 支持 `prefers-reduced-motion: reduce`；核心功能不依赖动画完成。

## 4. 非目标

- 不新增服务端接口、登录方式、账号找回系统、群邀请收件接口、公开 AI 商店或模型健康数据。
- 不改变现有权限、Run 状态机、消息幂等、配对方向或服务器地址优先级。
- 不在本轮实现深色主题；token 结构为后续主题保留空间，但只验收浅色主题。
- 不把静态原型、假数据或截图代码直接替换生产页面。
- 不部署生产站、不使用真实账号密码、不修改线上数据。
- 不为了视觉统一把所有页面强行做成同一种卡片网格。

## 5. 反目标

以下结果即使“看起来更炫”也视为失败：

- 大面积玻璃模糊、霓虹发光、持续高速运动或装饰粒子抢占阅读注意力。
- H5 很漂亮但 Android／小程序无法构建，或三端出现两套重复业务 UI。
- 用不可聚焦的 `view/text @tap` 继续冒充按钮、标签页和开关。
- 只靠颜色表示 AI、在线、失败、等待或选中状态。
- 通过 runtime CDN 加载图标、字体或 UI 资源。
- 直接修改 `dist` 构建产物压制 Vue Router 警告。
- 为了“完整”新增无真实数据来源的费用、token、在线、健康度、找回密码或通知设置。

## 6. 约束

- 技术栈保持 uni-app、Vue 3、TypeScript、Pinia、SCSS；继续使用当前锁定的 `@dcloudio/uni-*` 版本，除非为解决 A10 有经过验证的最小兼容调整。
- H5、App 和小程序继续共享同一业务页面和 Store；平台差异仅放在明确的条件编译或展示壳层中。
- shadcn-vue 依赖 DOM、Tailwind 与其组件运行时，不直接作为跨端页面依赖；只借鉴组件 anatomy、variant、focus ring、错误和禁用状态。
- 图标使用 Lucide 语义与笔画规范，通过本地、可审计、无网络依赖的生成资源或跨端组件交付。优先使用 Iconify 的 Lucide 数据作为构建期来源；若目标平台不可靠支持 SVG，则生成 PNG fallback。必须记录来源与许可。
- 所有页面继续使用真实 Store/API；测试可使用仓库 mock server 与虚构账号，禁止在自动化中使用真实凭据。
- 动画主要使用 `transform` 与 `opacity`，避免通过持续改变布局属性制造抖动。

## 7. 考虑过的实现方式

### 方式 A：只换皮和补动画

保留每页结构，只修改 `base.scss` 与局部样式。改动快、风险低，但无法解决重复控件、桌面布局、表单语义和无障碍问题；页面仍会是“统一颜色的十个手机页面”。不采用。

### 方式 B：跨端统一设计系统＋H5 桌面增强（采用）

抽取少量高复用组件和语义 token，逐页保持现有业务脚本，重构模板和布局；H5 使用共享桌面壳层／侧栏，App 与小程序保留移动端导航。动效与图标由跨端组件提供。成本中等偏高，但能一次解决一致性、可访问性、桌面体验和维护问题，且不复制业务逻辑。

### 方式 C：独立建立 shadcn-vue H5 应用

桌面端自由度最高，可以完整使用 shadcn-vue、Radix Vue 和 Tailwind，但会让 H5 与 uni-app 移动端形成两套页面、两套测试和两套交互状态。当前项目规模与维护目标不值得承担这种分叉，不采用。

## 8. 视觉系统

### 8.1 颜色

主色保持绿色，但从单一大色块改为分层语义：

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `--canvas` | `#F7F8F4` | 暖白页面底色 |
| `--surface` | `#FFFFFF` | 主要内容与表单 |
| `--surface-soft` | `#EFF4EC` | 次级面板、搜索、选中背景 |
| `--surface-mint` | `#E4F3D8` | 登录品牌面、成功和引导区域 |
| `--ink` | `#102A22` | 标题与高强调正文 |
| `--text` | `#23342D` | 正文 |
| `--text-muted` | `#5D6E66` | 摘要与辅助说明 |
| `--line` | `#D6DED7` | 分隔线 |
| `--control-line` | `#75827B` | 输入框与可操作边界 |
| `--accent` | `#176B4D` | 主操作与焦点 |
| `--accent-strong` | `#0B4935` | 高强调品牌墨绿 |
| `--accent-soft` | `#DDEFE5` | 选中、自己消息、成功弱背景 |
| `--ai` | `#7457C8` | AI 身份与少量紫色强调 |
| `--ai-soft` | `#EEE8FF` | AI 标签与头像背景 |
| `--cyan` | `#157F8F` | 连接、设备和实时状态 |
| `--danger` | `#A93632` | 错误与危险操作 |
| `--warning` | `#82590B` | 等待、需确认、结果未知 |

实现前以实际字号重新计算关键组合对比度；建议值不是自动通过无障碍验收的证明。

### 8.2 形态与排版

- 页面使用 4px 间距基准；移动端边距 16px，桌面内容间距 24–32px。
- 输入高 48px，主要按钮高 48px，桌面紧凑按钮不低于 40px，触控目标不低于 44px。
- 常规圆角 12px，强调卡片 16px，抽屉 20px；不使用每行独立阴影。
- 边框使用 1px 深浅明确的中性色；悬浮层才使用柔和阴影。
- 中文使用系统字体；标题字重 650–750，正文 400–500，避免所有标题都粗黑。
- 大面积品牌区使用薄荷绿底与深墨色线稿，不复制 BentoML 图形或 Nimbus 商标。

### 8.3 图标

- 统一采用 Lucide 风格：24×24 viewBox、圆角端点、约 2px 线宽。
- 一级导航、返回、添加、搜索、发送、设置、密码显隐、设备、用户、AI、状态、危险操作均使用图标＋必要文字。
- 纯图标按钮必须有可访问名称；不能用 `···`、`›`、`✕`、CSS 拼接或 emoji 作为正式图标。
- TabBar 图标继续生成本地普通／选中 PNG，其他图标由 `UiIcon` 统一渲染并在不支持的平台使用本地 fallback。

## 9. 布局系统

### 9.1 H5 桌面

- 登录页：左侧约 55% 动态品牌场景，右侧约 45% 表单；页面自行承担标题，不叠加 44px 原生导航。
- 已登录页：隐藏 H5 原生底部 TabBar，使用固定桌面侧栏；内容区按页面选择列表＋详情、两列设置或单列阅读布局。
- 会话：72px 导航轨＋320px 会话列表＋弹性聊天工作区；如果尚未选择会话，显示有用途的欢迎／快捷操作空态。
- 联系人：左侧搜索与分类，右侧联系人／申请内容；建群进入明确的选择步骤，不把控件堆在底栏。
- 我的／AI 详情／群设置／配对／运行详情：内容最大宽度 1080px，使用主区＋辅助区或两列分组；技术信息折叠到次级区域。
- 900–1099px 压缩侧栏和内容间距；768–899px 使用单列内容＋紧凑导航；低于 768px 回到移动结构。
- 桌面会话工作台复用同一聊天内容组件，而不是在会话页复制一套聊天实现；必须处理直接打开聊天 URL、刷新、浏览器返回、会话切换和跨断点切换时的生命周期与选中状态。

### 9.2 Android 与小程序

- 保留会话／联系人／我的三个一级 Tab，不新增第四 Tab。
- 次级页面使用统一自定义页面头或平台导航，不出现双标题。
- 列表、表单、抽屉和底部操作考虑安全区、软键盘、系统返回与字体放大。
- 聊天输入区始终停靠内容底部，不覆盖最后一条消息；弹层可滚动。

## 10. 动效系统

动效分为三类：

1. **进入与层级**：页面头、卡片和列表以 180–420ms 的错峰淡入／上移进入；一次最多错峰前 6 项，长列表不逐项延迟。
2. **操作反馈**：按钮按压、悬停、焦点、分段切换、抽屉和展开区使用 120–280ms 过渡；禁用态不响应缩放。
3. **状态表达**：生成中用三点节奏，连接中用缓慢轨迹／脉冲，加载骨架用低对比微光，成功用一次性描边或弹入，`recovery_required` 使用静态警示而非成功动画。

登录品牌场景由三层构成：

- AI／HUMAN／CHAT 文字错峰进入，借鉴 APC 左侧的节奏但重新设计内容与配色；
- 人类、AI 和群聊节点通过本地线稿连接，轨迹点缓慢移动；
- 两到三个消息卡片轻微漂浮，内容使用产品真实能力文案，不展示虚构统计。

所有持续动画周期不短于 2.4s，并限制在小面积装饰或真实状态区域。`prefers-reduced-motion: reduce` 下移除位移、循环和错峰，只保留立即显示或短淡入。

## 11. 共享组件边界

计划新增或整理以下职责；具体文件名在实施计划中锁定：

- `AppShell`：H5 桌面导航与页面内容槽；移动端不复制平台 TabBar。
- `PageHeader`：标题、副标题、返回和主要操作。
- `UiIcon`／图标生成器：本地 Lucide/Iconify 来源与跨端 fallback。
- `UiButton`：primary、secondary、ghost、danger、icon variants；真实 button 语义。
- `FormField`：label、hint、error、输入 ID、`aria-invalid` 和错误关联。
- `SegmentedControl`：真实可聚焦 tab／button 行为和选中状态。
- `AccountAvatar`／`IdentityBadge`／`StatusBadge`：人类、AI、群与状态的统一表达。
- `SurfaceCard`／`SettingsSection`：卡片和设置分组，不承载业务逻辑。
- `EmptyState`／`InlineNotice`／`SkeletonList`：空、错误、警示和加载状态。
- `BottomSheet`：遮罩、焦点返回、Esc／返回键、滚动和安全区。

组件不直接调用 API 或 Store；页面保留业务编排，避免把领域逻辑藏入视觉组件。

## 12. 页面设计

### 12.1 登录／注册

- 完整解决 A01—A10；模式切换为真正按钮／tab，表单提交共用单一路径。
- 每字段有 label、name、autocomplete、持久错误、`aria-invalid` 和首错聚焦。
- 登录账号提示改为“请输入账号名”；注册说明唯一性。密码支持显隐。
- “忘记密码”不伪造找回流程，展示“请联系管理员重置账号访问”的可发现说明。
- 服务器设置作为折叠的自托管高级选项，分别提示缺协议、缺主机、含路径等错误。
- 切换模式同步页面主标题、浏览器标题和可访问标题。

### 12.2 会话

- 列表增加页面头、本地筛选、清晰的新建按钮、统一头像和身份标签。
- 行内突出名称与最新消息，时间和未读为次级信息；选中、悬停、按压有反馈。
- 空态给出“找联系人”和“创建群聊”两个真实入口。
- H5 桌面展示会话工作台；移动端保持点入聊天。

### 12.3 联系人

- 搜索与本地联系人筛选分开，精确账号搜索不伪装成模糊发现。
- 联系人／申请使用真正分段控制；收到、发出申请明确分组。
- 建群改为选择成员→填写群名→确认邀请的可理解流程；邀请发送不写成已加入。
- 危险操作保留确认；常用“发消息”优先，更多操作使用图标菜单。

### 12.4 聊天

- 消息正文、头像、名称、AI 标签、引用和运行状态重新分层；AI 长回答使用更宽内容块。
- H5 Enter 发送、Shift+Enter 换行，并保护中文输入法 composition；手机由发送按钮触发。
- 用户向上浏览历史时不强制滚到底部，显示“有新消息”浮动入口；贴近底部时才跟随。
- 生成、断线、取消、失败和结果未知分别使用真实状态动效与文案。
- @AI 选择、引用条、输入区和 BottomSheet 使用真实按钮和焦点管理。

### 12.5 我的

- 个人资料为页面头区；设置分为“AI 与设备／账号／高级”三组。
- 我的 AI、连接设备、登录会话使用统一图标和说明；服务器地址移入高级设置。
- 编辑资料和服务器设置使用内联表单或 BottomSheet，不把所有内容同时展开。
- 退出登录独立为危险操作区。

### 12.6 我的 AI

- 使用响应式卡片网格；每张卡明确身份、简介、接入类型、配置状态和可核实的连接信息。
- “创建 AI”作为唯一主操作；空态解释 AI 独立账号和两种接入方式。
- 不把 connector online、binding enabled 或配置存在写成模型业务已验证。

### 12.7 AI 详情

- 页面分为资料、接入方式、使用授权和连接设备四个区块。
- 模型密钥只在绑定表单输入；绑定后只显示脱敏摘要。
- 编辑、授权、绑定和撤销使用清晰层级；危险撤销不与主要保存按钮并排混淆。
- 技术字段和内部 ID 放入折叠详情。

### 12.8 群设置

- 顶部展示群名、成员概况和状态；成员列表统一身份／角色标签。
- 权限决定按钮是否存在，而不是仅将无权按钮变灰。
- 邀请成员使用 BottomSheet；角色变更和群主转让有明确确认文案。
- 退出与解散独立在危险区；历史可见范围用准确文字说明。

### 12.9 配对

- 改为步骤式流程：获取配对信息→核对设备和确认码→选择 AI→批准／等待设备确认。
- 扫码为移动端主操作，H5 明确显示手动输入。
- 配对 ID 与短码作为必要技术输入保留，但用帮助文字解释，不让用户先看到内部术语。
- 状态轮询有可见但克制的连接动效；终态停止动效。

### 12.10 运行详情

- 首屏先回答“哪个 AI 在处理什么、当前状态、下一步是什么”。
- 原始 ID、attempt、generation 和时间字段放在技术详情折叠区。
- active、success、failed、cancelled、recovery_required 使用不同图标、文字和弱背景，不只换颜色。
- `recovery_required` 强调先核查再决定是否重试；保留现有服务端权限判断。
- 保留当前交互差异：运行详情页可在核查后创建新运行，聊天页不直接提供该状态的重试按钮；本轮只强化说明和确认，不擅自统一或改变状态机。

## 13. 评测问题映射

| 问题 | 设计响应 |
| --- | --- |
| A01 | 真实 form/button/tab，统一 submit 与键盘路径，清晰 focus ring |
| A02 | `FormField` 生成 label/id/error 关联，验证最终 H5 DOM |
| A03 | 字段级持久错误＋摘要／Toast，首错聚焦，URL 原因细分 |
| A04 | username/current-password/new-password 等自动填充语义 |
| A05 | 可发现的管理员重置说明，不虚构恢复流程 |
| A06 | 全局 placeholder token，实测对比度至少 4.5:1 |
| A07 | 登录页 custom navigation／正确可用高度，不再叠加 44px |

## 14. 错误与状态策略

- 表单错误保留到字段修正或再次提交；Toast 只作为补充，不是唯一反馈。
- 页面请求失败显示可重试 InlineNotice，不渲染成空列表。
- 禁用态必须说明原因；不能只有低透明度。
- 列表加载使用骨架，操作提交使用按钮局部 loading，避免整页闪烁。
- 破坏性操作继续用确认弹窗，并明确影响对象。
- WSS 断线文案只描述“实时连接恢复中”，不推断 AI 离线。
