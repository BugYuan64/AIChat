# 账号与权限

## 统一身份与术语

本文是身份、联系人、成员与历史授权的权威规则；表约束见[数据模型](数据模型.md)，接口见[消息契约](消息与HTTP-WSS契约.md)。
account 是平台身份，actor 是它参与会话时的称呼，不另建互相漂移的 actor 主键。
线协议统一用 account_id；消息使用 sender_account_id；agent_id 同时是 kind=agent 的 account_id。
account.kind 仅有 human/agent；owner_id 是 agent 所属的 human account_id，不是厂商用户 ID。
同厂商实例各有 account/agent，不能用 provider 名称作为账号或会话隔离键。

| 对象 | 身份与凭据 | 可以做什么 | 不能做什么 |
| --- | --- | --- | --- |
| human | human session、短期访问票据 | 按成员角色聊天，管理自己的 agent | 使用 owner_id 旁路读取群历史 |
| agent | 平台 account；无 human 密码登录 | 作为成员产生受控任务结果 | 自行注册人类、任意邀请或批准自己 |
| runner | 绑定 owner+agent 的设备、独立 credential | 领指定任务、回报进度、请求审批 | 使用 human 接口、列举全部群历史 |
| 平台运维 | 运维角色，与业务会话授权分开 | 最小运维与审计 | 默认充当群成员或随意查正文 |

human 首期登录方式待 D1 决定，可采用自托管邀请开户方案；当前没有实现注册或认证。
human token 的 audience、session_id 与 runner token 的 audience、runner_id 严格不同。
普通用户不能把 account.kind 改为 human，agent 不能经消息字段伪装 human。

## owner 与多所有者隔离

每个 agent 只有一个 owner；一期不开放所有权转移，未来转移需撤销旧设备并重新审批。
owner 创建/停用 agent、管理 runner 与能力上限，不能修改别人的 agent 或替其批准配对。
runner 一期绑定单个 agent；一个 agent 可登记多 runner，但每次 attempt 只租给其中一个。
owner 只得到运行状态和必要审计摘要，不自动收到 agent 所在群的正文或消息事件。
runner 设备实际处理被分配的上下文，设备操作者可能看到该数据；邀请页面须披露运行设备归属和信任边界。
这不等于授予 owner 通过平台 API 读取群历史的权利；不信任设备操作者时不要邀请该 AI。
多个 human 的数据不依赖单一“当前用户”全局变量隔离，所有查询以请求主体与对象授权为条件。

## 联系人与私聊

human-human 联系申请由对方接受；contact 存规范化双方 ID、申请方向及 pending/accepted/blocked 状态。
human-agent 联系需 agent owner 接受；owner 联系自己的 agent 可在服务端自动确认并审计。
一期不提供公开全量账号搜索；通过明确账号标识或邀请发起，返回有限资料并限制枚举。
accepted contact 允许创建双方私聊；创建时检查账号可用及阻止状态，并发以规范化双人键唯一约束去重。
私聊双方固定，不允许把同一 direct 会话变成群；多人会话另建 group。
阻止关系立即停止新的私聊发送与调度，既有历史仍受成员规则约束；不能通过重建第二个 direct 绕过。
一期允许 human-human、human-agent direct；AI-AI direct 和纯 AI group 仅保留模型，创建接口拒绝。

## 群角色与 AI 邀请

| 行为 | 群主 | 管理员 | 普通 human 成员 | agent |
| --- | --- | --- | --- | --- |
| 读本次成员区间历史/发普通消息 | 是 | 是 | 是 | 仅任务授权上下文及任务结果 |
| 邀请 human / 发起 AI 邀请 | 是 | 是 | 申请管理者处理 | 否 |
| 移除普通成员/agent | 是 | 是 | 否 | 否 |
| 任免管理员/转让群主 | 是 | 否 | 否 | 否 |
| 开启协作/紧急停全群任务 | 是 | 停止可以，开启不可以 | 取消自己的任务 | 否 |
| 退出 | 先转让或解散 | 是 | 是 | owner 可请求移除自己的 agent |

管理员不能移除群主或其他管理员，群主不能是 agent；群始终至少一个 active human。
AI 入群要两项同意：群主/管理员准入，以及该 AI owner 对此 conversation 的明确批准。
两项同意须在同一邀请有效期内，最终事务复查双方身份、角色、agent 状态和邀请版本，再激活 member。
owner 恰是邀请管理员时可一并确认，但仍记录两种授权的依据，不默认给该 owner 新增群成员身份。
拒绝/过期不创建 active member；重复接受只返回同一结果，不能多发成员事件。
邀请只含有限群资料，不让尚未入群的 owner 或 agent 预读消息历史。

## 历史与授权时点

member 用 membership_id 标识一次加入，含 visible_from_seq 和可选 left_seq，重新加入创建新记录。
默认加入边界为事务内 conversation.last_seq+1；不开放本次加入前的群历史。
退出/移除后不再允许服务器读取或补拉该会话任何正文，包括旧期间内容；既有下载副本无法远程收回。
重新加入默认只见新 membership 的区间，不恢复之前区间；一期不做管理员回填历史。
系统成员变更通知也占 message seq，加入通知可成为新成员第一条可见消息。
每次读消息、补事件、标已读、发消息及 start/delta/finish 都检查账号、active membership 与区间。
owner_id 不参与消息授权的 OR 条件；联系人关系也不能扩大成员可见范围。
run 上下文取 human 发起者与目标 agent 当前可见区间的交集，且必须包含触发消息，否则不创建/执行。
不向新加入 AI 补发更早消息，不把 owner 的其它私聊或运行时其它 session 拼进上下文。
sender_account_id 由服务器从 human session 或 runner 对应 agent 推导，客户端提供 sender_id 等身份字段直接拒绝。

## 撤权与竞态

conversation 行锁统一串行化消息发送、成员变化与 run 权限快照，按锁获得后状态决定提交结果。
若移除先提交，后续发送/start/结果提交失败；若消息先提交，之后仍须依据读取时授权过滤。
成员变化递增 auth_version，失效缓存并清理待推送项；每次投递前复查，不能只广播给旧连接名单。
退出 agent/禁用 agent/撤销 runner 时停止新派发，并向已有 attempt 发取消；不可确认副作用时标 unknown。
human 退出会话后，由其触发而尚未完成的 run 同样停止，不继续以旧授权处理。
工具审批必须绑定 run、attempt、fencing_epoch、参数摘要与 policy_version；任一变化就使旧批准失效。
执行前按同一规范化摘要复核真实操作并原子消费一次，路径、命令或目标资源变化须重新审批；批准后崩溃不得复用旧批准重放副作用。
撤销不能撤回已发往网络的数据或已执行的工具，界面明确报告无法确认的结果，并保留审计。

## 工具与协作权限

普通群消息、AI 输出、提示注入及自报 capabilities 都不构成授予文件/命令/网络/推送权限的依据。
有效能力是平台上限、owner 策略、群策略、任务授权和 adapter 实测支持的交集。
模型推理所需出网地址在接入时由 owner 以白名单授权并受任务预算限制；工具的任意网络访问不继承此授权。
涉及本地工作区写入、命令或外网操作时，还需有权批准该设备资源的 owner 对具体操作审批。
聊天任务发起者不自动拥有别人的设备授权；群管理员也不能替 owner 放宽设备策略。
task 的 policy_version 标识有效策略快照，包含 owner 配置修订、会话授权版本与 adapter 能力修订；任一变化均需重新核验。
adapter 不能强制隔离或逐操作审批时，相应高风险能力必须关闭；仅靠提示词“不要写文件”不能声称隔离。
协作默认关闭，AI 只提议下一目标，平台按策略生成子 run，完整预算规则见[统一 AI 接入](统一AI接入.md)。

## 审计与验收

记录开户/禁用、成员变化、配对批准、凭据撤销、策略修改、审批和异常终态的 actor 与对象摘要。
审计不能成为正文旁路；日志不包含 token、device_code、完整提示词或厂商 key。
负面用例及验收编号见[设计决策与验收](设计决策与验收.md)，本轮未运行授权测试。
